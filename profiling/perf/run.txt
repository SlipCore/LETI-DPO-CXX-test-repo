1. Собрать perf
sudo ./perf.sh

2. Не очень безопасные настройки для системы, но они нужны для корректной работы perf
echo -1 | sudo tee /proc/sys/kernel/perf_event_paranoid
echo 0 | sudo tee /proc/sys/kernel/kptr_restrict

3. Комиляция
g++ -g -o perf perf.cpp -lm

4. Запуск с перфом
perf record -g ./perf

5. отчет
perf report

6. 
perf list

тут интересный показатель insn per cycle (IPC) -- он показывает, сколько в среднем инструкций выполняется за один такт процессора. 
Если IPC > 2.5 это хорошо
Если  1 < IPC < 2.5 -- неплохо, но можно подумать над оптимизацией
Если IPC < 1, то это плохо, процессор простаивает и нужно искать причины:
1. промахи в кэш (нелинейный доступ, огромные струруктуры, которые не влезают в кэш, нелоклаьное хранение данных, например, не в массиве, а списке)
2. проблемы с непредсказуемым ветвлением (сложные большие условия)
3. высокая зависимость данных (выполнение инструкции зависит от выполнение множества других иснтрукций)
4. много системных вызовов (read write malloc и тд) + блокировки памяти


7. 
perf stat -e dTLB-loads,dTLB-load-misses ./<имя исполняемого файла>

Показывает, насколько эффективно кэшируются инструкции

perf stat -e dTLB-loads,dTLB-load-misses ./<имя исполняемого файла>
